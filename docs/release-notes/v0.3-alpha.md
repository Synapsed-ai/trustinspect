# TrustInspect v0.3-alpha Release Notes

## Status

Early open-source alpha. Release hardening is under review; full release validation remains required.

## Highlights

- Web UI scanner with Selenium
- Static baseline testing
- Target capability profiling
- Dynamic/adaptive test generation
- Dynamic template engine with risk mapping
- Structured failure indicators and safer match semantics
- Evidence-based observations and findings
- HTML report with Target Capability Profile and Generated Test Plan
- Prompt/response expandable details
- CLI phosphor terminal UI
- Report sanitization with untrusted content escaping
- Catalog and template validators

## Key CLI commands

```bash
trustinspect scan-web ...
trustinspect profile-target ...
trustinspect adaptive-scan ...
python -m trustinspect.dynamic.engine ...
python -m trustinspect.testcases.validator ...
python -m trustinspect.dynamic.validate_templates ...
```

## Known limitations

- Web UI selector discovery remains target-dependent.
- Web UI mode is single-session and should run sequentially.
- Dynamic generation is deterministic-template based; no LLM-assisted generation yet.
- Agentic adapters are planned but not complete.
- API mode and RAG trace support need further hardening.

## Next milestones

## Hardening changes under review

- Test-specific failure evidence is evaluated before generic refusal wording.
- Empty/operational-error responses are not classified as safe behavior.
- Response capture uses pre-submission node identities and a quiet interval, with an optional target-specific busy selector.
- Report data is escaped for all HTML templates, including `.html.j2`.
- Runtime guards inspect executable syntax instead of matching old patch strings.

A quiet interval is a streaming heuristic, not an end-of-stream guarantee. Regex
indicators and English-language refusal matching still require scenario-specific
validation. API and agent-trace adapters are not implemented by this patch.
