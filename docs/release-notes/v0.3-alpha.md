# TrustInspect v0.3-alpha — release notes draft

The repository is public and the technical hardening from PRs #1–#3 is integrated; PR #4 restored the approved presentation. These notes describe the first-alpha scope. They do not announce a published release. Package metadata remains `0.3.0a0` pending an explicit version/tag decision.

## Included

Selenium Web UI scanning, interactive launcher, target calibration and registry, five baseline/OWASP suites, target capability profiling, deterministic contextual test variants, and evidence-based HTML/JSON assessment output. The bundled vulnerable/hardened local chatbot supports repeatable integration checks without a paid AI endpoint.

## Integrated hardening

Test-specific failure evidence is considered before generic refusal wording. Missing responses, operational-error text and malformed indicator definitions are not treated as safe behavior. Catalog validation and analysis share indicator normalization. Textual claims and raw markup remain review signals when they do not prove actual side effects. Response capture identifies the current turn; multiline prompts are inserted without premature keyboard submission. HTML template data is escaped, and runtime guards examine executable syntax.

Runtime catalogs and templates are packaged with the application. Installed-package checks run outside the checkout, and local target overrides do not mutate installed resources. Ordinary and dedicated real-browser regressions remain separate, with explicit skip reporting in the ordinary suite.

## Release preparation

The dependency review raises necessary Jinja2, wheel, setuptools and pytest floors; audits exact resolved runtime/build/test packages; records platform-specific versions and hashes; emits a runtime SBOM; and replays the hashed installation. See [dependency policy](../release/dependency-policy.md) and [publication checklist](../github-publication-checklist.md).

The presentation retains its three videos, positioning matrix and six screenshots. Only the approved event labels in two historical screenshots were removed; their test outcomes were not edited.

## Known limitations

Web UI selectors remain target-dependent and execution is sequential/single-session. A quiet interval is a streaming-completion heuristic, not a universal guarantee. Dynamic generation is template-based, not autonomous response-guided attack planning. Regex predicates and English-language refusal patterns require scenario-specific validation. Passing deterministic demo tests does not establish real-model detection accuracy.

Native API, RAG/vector-store and agent-trace adapters are not implemented in this alpha. A Web UI may expose a RAG or agentic application's behavior, but that is not native access to its retrieval or tool-call traces. Private vulnerability intake and content-provenance sign-off remain explicit release gates until confirmed by the maintainer.
