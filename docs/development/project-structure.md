# TrustInspect Project Structure

TrustInspect should separate runtime code, reusable assets, test suites, target profiles, dynamic templates, generated artifacts, demos, and maintenance scripts.

## Runtime code

```text
trustinspect/
  analyzers/
  core/
  dynamic/
  evidence/
  findings/
  interactive/
  reporting/
  scanners/
  suites/
  targets/
  testcases/
  ui/
```

## Static assets

```text
assets/
```

Used for report headers and other static UI/report assets.

## Static test suites

```text
suites/
  trustinspect_baseline.yaml
  owasp_llm_top10_2025_light.yaml
  owasp_llm_top10_2025_full.yaml
```

Legacy locations such as `examples/test_cases/` and `examples/test_suites/` should be treated as compatibility paths only.

## Dynamic templates

```text
dynamic_templates/
```

Reusable templates used by the Dynamic Test Engine.

## Targets

```text
targets/
  builtin/
  local/
  disabled/
```

`targets/builtin/` is versioned. `targets/local/` is generated by calibration and should be gitignored.

## Generated artifacts

```text
reports/
generated_tests/
profiles/
```

These are generated during scans and should normally be gitignored.

## Demos

```text
demos/
  trustinspect-demo-chatbot/
```

Controlled reproducible demos, including vulnerable/hardened configurations.

## Maintenance

```text
tools/maintenance/
```

Audit, cleanup, migration, and release utilities. Temporary patch scripts should not live in the repository root.
